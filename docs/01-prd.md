## 0. 文档说明

> 本 PRD 仅覆盖 **MVP 范围（Phase 1，第 0~6 周）**。  
> Phase 2+ 的功能将按里程碑节奏单独立 PRD（如 `01-prd-p2-ugc.md`）。

**北极星目标（永远围绕这个判断）**：
> **打造最好用的拼豆小程序，让用户从「想做」到「真的做出来」的链路丝滑无障碍。**

**产品灵魂三句话（每个决策的试金石）**：
1. **零智商税** —— 用户不需要懂任何技术，不需要数颗数、不需要选色卡、不需要担心库存
2. **把感情做成礼物** —— 拼豆不是塑料玩具，是承载具体回忆的有形之物（自家猫、伴侣、孩子的画）
3. **在心流中找回自我** —— 重复性手作 = 当代人的低成本解压方式，让用户在 2 小时里只跟豆子和自己相处

每条用户故事 / 每个验收标准都必须能回答："这条让用户更接近完成第一件作品了吗？"

**用户故事（US）格式**：`作为<角色>，我希望<功能>，以便<价值>`

**验收标准（AC）规则**：
- 每条 AC 必须**可测**（能被一个具体动作验证）
- 用 `[ ]` 复选框，开发完成时打勾
- 性能/数据指标必须**有数字**，禁止"快""流畅"等模糊描述
- 不确定的决策用 `[NEEDS CLARIFICATION]` 显式标注

## 1. 产品概述

### 1.1 一句话产品定义
> 一款能把用户照片自动转化为可购买的拼豆图纸 + 精确算料 + 一键下单的小程序。

### 1.2 灵魂差异化（"最好用"的硬核定义）

对比市面竞品（淘宝散卖、外网 Beads Creator、海外网站工具），我们必须做到：

| 维度 | 竞品现状 | 我们的解决 | 用户感知 |
|---|---|---|---|
| **不知道买什么颜色多少颗** | 用户拿图自己数，错率高 | 算料表精确到颗，含 +10% 安全冗余 | "傻瓜式买齐" |
| **买不齐色号** | 缺货只能放弃或换图 | 实时库存约束 + CIE Lab 智能替换 | "永远买得到" |
| **不知道做出来多大** | 拼到一半发现尺寸不对 | 第一屏可见实物尺寸 + A4 / 手机对比图 | "心里有底" |
| **不知道难不难** | 一上来就翻车 | 三档难度 + 预计耗时提示 | "选我能做的" |
| **怕熨斗烫伤孩子** | 没人提醒 | 首单强制安全提示 + SGS 标识 | "敢让孩子参与" |
| **做出来想晒** | 完成后没动力分享 | 完成页一键生成"对比图"分享卡 | "出片快" |

> ⚠️ **以上 6 点是 MVP 的产品灵魂，每一点都对应 P0 用户故事。任何砍 P0 的提议都必须先证明不影响这 6 条。**

### 1.3 MVP 目标（M1 决策门对齐）

| 维度 | 指标 | 目标值 |
|---|---|---|
| **链路完整性** | 上传 → 生成 → 支付 → 收货 端到端跑通 | 100% |
| **算法质量** | 100 张样图人工评分优良率 | ≥ 75% |
| **算法性能** | P95 端到端处理耗时 | ≤ 10 秒 |
| **支付转化** | 生成图纸 → 支付完成 | ≥ 15% |
| **安全合规** | SGS 认证 + 安全提示覆盖率 | 100% |
| **审核通过** | 微信小程序审核 | 通过并上线 |

### 1.4 MVP 不做的范围（明确边界）

- ❌ UGC 社区（Phase 2）
- ❌ 代拼撮合（关联 ADR-010 → 推迟到 Phase 2，详见 §11.1）
- ❌ 抖音小程序（Phase 2 W11）
- ❌ 线下 SaaS（Phase 2 W9）
- ❌ IP 授权图纸（Phase 4）
- ❌ NSFW 内容（永不做）
- ❌ 智能拼豆板硬件（Phase 3+）
- ❌ 多语言（仅简体中文）

## 2. 目标用户（详见 [`./02-personas.md`](./02-personas.md)）

### 2.1 MVP 焦点：单 Persona 优先

> ⚠️ **关键决策**：MVP 优先服务 **P1 小薇（小红书晒图族）**，其他 Persona 是"附带兼容"。  
> 单人项目精力有限，多 Persona 平行优化 = 谁都做不好。

**理由**：
- P1 流量便宜（小红书 KOL CAC 低）
- P1 客单价高（情感消费 80~150 元）
- P1 自带传播节点（小红书出片自带分享）
- P2 安全顾虑可以靠"安全提示组件"统一兜底，不需要单独定制流程

**`[NEEDS CLARIFICATION]`**：是否同意 MVP 仅聚焦 P1？  
- 推荐：✅ 是
- 备选：照顾 P2 → 首页加"亲子专区"入口，AC 工作量 +20%

### 2.2 P1 用户的核心场景（指导功能取舍）

```
场景：周日下午，小薇刷小红书看到「自家猫做成拼豆」笔记，被种草
        ↓
        点进小程序（首次访问）
        ↓
        【必须 30 秒内做出第一个判断】
        - 这个能做我家猫吗？
        - 大概多少钱？
        - 难不难？
        ↓
        如果以上都 OK → 上传照片
        ↓
        【必须 10 秒内看到生成结果】
        - 像不像？
        - 多大？
        - 多少钱？
        ↓
        加购 → 支付 → 收货 → 拼好后晒图
```

**指导原则**：MVP 所有功能优先级取决于"是否帮助小薇通过这个场景的某一步"。

## 4. 用户故事详细规格（v0.5 详化）

### M0 · 首屏与种草说服（**新增**）

> **设计原则**：用户从小红书点进来时是"半信半疑"状态，30 秒内必须打消三个疑虑：能做我的？多少钱？难不难？

#### US-0.1 首屏 30 秒说服
**作为** 从小红书种草来的小薇  
**我希望** 一打开小程序就立刻明白"这能干嘛、做出来啥样、大概多少钱"  
**以便** 决定是否值得花 5 分钟试一下

**验收标准**：
- [ ] 首屏（不滚动）必须包含 4 个元素：
  - [ ] 主标题：「把你的照片，变成可以触摸的礼物」
  - [ ] 主 CTA：「上传一张照片试试 →」（橙色大按钮，60% 屏宽）
  - [ ] 价格锚点：「定制拼豆 ¥69 起」
  - [ ] 真实案例展示位（轮播 3 张："自家猫"/"情侣照"/"宠物狗" → 拼豆成品对比图）
- [ ] 不允许：弹窗广告、强制登录、需要用户做决策的菜单
- [ ] 首屏加载耗时 ≤ 2 秒（小程序基础库 ≥ 2.20）
- [ ] 触发埋点：`page_viewed (page_path=/home)`

**异常流**：
- 首次进入未登录 → 不强制登录，直到「上传」时再调起 `wx.login`

**衡量指标**：首屏到点击「上传」的转化率 ≥ 40%（埋点漏斗 step1→step2）

---

#### US-0.2 价格透明度（核心信任）
**作为** 第一次来的用户  
**我希望** 在上传照片前就能看到大致价格区间  
**以便** 不会因为"做完才发现要 200 块"而流失

**验收标准**：
- [ ] 首页二屏可见「价格说明」卡片：
  - [ ] 简单档（16x16）：约 ¥49~69
  - [ ] 普通档（32x32）：约 ¥69~99
  - [ ] 专业档（64x64+）：约 ¥99~159
- [ ] 价格区间基于真实供应商报价 + 安全冗余（关联 ADR-008）
- [ ] 价格说明可点击展开「为什么这个价」（成本透明：豆子 + 配件 + 包装 + 物流）

**`[NEEDS CLARIFICATION]`**：是否做"价格估算器"（用户输入照片复杂度预估价）？
- 推荐：MVP 不做，先用静态价格区间（数据沉淀后再做）

---

#### US-0.3 真实案例瀑布流
**作为** 想看效果的用户  
**我希望** 滑动看到真实买家的"原图 → 拼豆成品"对比  
**以便** 建立"这真的能做出好看东西"的信心

**验收标准**：
- [ ] 首页三屏开始展示瀑布流，每个 item：原图 + 成品图 + 用户简短评价
- [ ] MVP 阶段使用「官方种草样本 + 内测用户授权图」≥ 30 张
- [ ] 点击 item 跳转该图纸详情页，可「同款下单」
- [ ] 触发埋点：`case_card_clicked (case_id)`

**`[NEEDS CLARIFICATION]`**：MVP 阶段是否允许用户主动上传"我也做了"晒图？
- 推荐：MVP 不开放（变成 UGC 社区会偏离主线，Phase 2 再做）

---

### M1 · 上传与抠图

#### US-1.1 拍照/相册上传图片
**作为** 已下决心试试的用户  
**我希望** 用最少的步骤上传一张照片  
**以便** 立即看到效果

**验收标准**：
- [ ] 「上传」按钮触发后立即调用 `wx.chooseMedia({ count: 1, mediaType: ['image'] })`
- [ ] 不强制登录（先选图，支付时再 `wx.login`）
- [ ] 限制：JPG / PNG，单张 ≤ 10 MB，最小 256×256
- [ ] 文件超限时提示：「这张照片太大啦，建议 ≤ 10MB」+ 提供"选另一张"按钮
- [ ] 上传中显示进度条（百分比 + 取消按钮）
- [ ] 网络异常 3 秒内重试 1 次，再失败提示：「网络好像不太顺，要不再试一下？」+ 重试按钮
- [ ] 上传成功后**自动**进入裁剪页（不需要点"下一步"）
- [ ] 触发埋点：`image_upload_started` / `image_upload_completed` / `image_upload_failed`

**异常流**：
- 用户拒绝相册权限 → 提示「需要相册权限才能上传哦」+ "去设置"按钮
- 上传到 OSS 失败 → 临时缓存到本地，下次启动时重试（最多 3 次）

---

#### US-1.2 图片裁剪
**作为** 上传了照片的用户  
**我希望** 把照片裁剪成合适比例  
**以便** 主体居中，做出来的拼豆构图好看

**验收标准**：
- [ ] 默认提供 4 种裁剪比例：1:1（正方形 / 默认）/ 4:3 / 3:4 / 自由
- [ ] 默认裁剪框居中并自动适配 1:1（拼豆最常见尺寸）
- [ ] 支持手势：拖拽位置、双指缩放
- [ ] 支持旋转（90° 步进）
- [ ] 顶部固定操作栏：「重选」「旋转」「确认」三个按钮
- [ ] 「确认」后进入难度选择页（M4）
- [ ] 触发埋点：`image_cropped (aspect_ratio, rotation)`

---

#### US-1.3 自动抠图（背景剥离）
**作为** 上传了带杂乱背景照片的用户  
**我希望** 系统自动剔除背景，让主体清晰  
**以便** 拼出来的成品有焦点不糊

**验收标准**：
- [ ] 用户在难度选择页确认后，后端**异步**调用抠图（rembg 主选 / grabCut 备选）
- [ ] 端到端耗时 P95 ≤ 5 秒
- [ ] 处理中前端显示进度提示（"正在为你抠图…"+ 像素风 loading 动画）
- [ ] 处理失败时不阻塞流程：自动降级为"不抠图"（直接进入像素化），并在结果页提示"抠图失败，可手动调整"
- [ ] 触发埋点：`cutout_completed (duration_ms, engine)` / `cutout_failed`

**关联文档**：[`./07-algo-spec.md`](./07-algo-spec.md) §3.2

---

#### US-1.4 手动微调（兜底，可降级）
**作为** 算法抠图不准的用户  
**我希望** 手动涂抹保留 / 移除区域  
**以便** 不被算法卡住

**验收标准（MVP 简化版）**：
- [ ] 在图纸预览页（M2）提供「重新生成（关闭抠图）」按钮
- [ ] 点击后图纸基于"未抠图"的原图重新生成
- [ ] 不实现复杂的"涂抹工具"（Phase 2 再做）
- [ ] 触发埋点：`cutout_disabled_by_user`

**`[NEEDS CLARIFICATION]`**：MVP 是否就此降级版本即可？
- 推荐：✅ 是（涂抹工具开发成本高，MVP 用"重新生成"足够）

### M2 · 图纸生成（**核心算法链路**）

#### US-2.1 选择图纸尺寸（网格规格）
**作为** 选完难度的用户  
**我希望** 系统自动推荐一个合适的尺寸，但允许我修改  
**以便** 不用纠结技术参数

**验收标准**：
- [ ] 难度档与默认尺寸映射：
  - [ ] easy → 默认 32x32
  - [ ] normal → 默认 48x48
  - [ ] pro → 默认 64x64
- [ ] 每档支持上下浮动 1 级（如 normal 可选 32x32 / 48x48 / 64x64）
- [ ] 每个尺寸显示「成品尺寸（cm） + 预计耗时（小时）+ 价格区间（元）」
- [ ] 选择尺寸时实时刷新这三个数（不需要重新生成图纸）
- [ ] 触发埋点：`grid_size_selected (grid_size, difficulty)`

---

#### US-2.2 算法生成像素图纸
**作为** 选好参数的用户  
**我希望** 系统在 10 秒内生成一张高质量的像素图纸  
**以便** 立即看到效果

**验收标准**：
- [ ] 调用算法引擎管线（关联 [`./07-algo-spec.md`](./07-algo-spec.md) §1）
- [ ] 端到端处理耗时 P95 ≤ 10 秒（M1 决策门硬指标）
- [ ] 输出：像素矩阵 + 各色号颗粒数 + 预览图 + 尺寸 + 替换比例
- [ ] 颜色仅取自"可售"色号（库存约束，关联 ADR-004）
- [ ] 缺货色号自动用 CIE Lab 最小色差替换
- [ ] easy 档自动描边（增强辨识度）
- [ ] 强制无抖动（物理拼豆必须）
- [ ] 处理中显示「AI 正在为你设计专属图纸（约 8 秒）」+ 进度提示
- [ ] 处理失败时不立即报错，先重试 1 次
- [ ] 触发埋点：`pattern_generate_started` / `pattern_generate_completed (duration_ms, color_count, substitution_ratio)` / `pattern_generate_failed`

**异常处理**：
- 算法服务超时（>15s）→ 返回「网络好像有点慢，再试一下？」+ 重试
- 算法连续失败 3 次 → 提示「换张照片试试，可能这张比较特殊」+ 客服入口

---

#### US-2.3 重新生成
**作为** 对结果不满意的用户  
**我希望** 一键重新生成一次  
**以便** 不用从头开始上传

**验收标准**：
- [ ] 预览页右上角「重新生成」按钮
- [ ] 同图同参数最多 3 次免费重生成（防滥用算力）
- [ ] 第 4 次起需要观看广告 / 消耗 PX 积分（MVP 简化：弹窗提示「已经试过 3 次啦，要不要换张图？」+ 「换图」按钮）
- [ ] 触发埋点：`pattern_regenerated (attempt_count)`

---

#### US-2.4 单格修改
**作为** 完美主义用户  
**我希望** 点击单个格子修改颜色  
**以便** 微调不满意的细节

**验收标准（MVP 简化版）**：
- [ ] 预览页支持双指缩放查看像素细节（最大 5 倍）
- [ ] 点击单个格子弹出「色号选择器」（可选可售色号列表）
- [ ] 修改后实时刷新预览图 + 算料数量 + 价格
- [ ] 单次修改格数 ≤ 50 格（防误操作）
- [ ] 「重置」按钮可恢复算法原版
- [ ] 触发埋点：`pattern_cell_modified (cell_count)`

**`[NEEDS CLARIFICATION]`**：单格修改是否纳入 MVP？
- 推荐：✅ 简化版纳入（缩放 + 点击改色，不做高级功能如撤销/批量替换）—— 因为是"完美主义用户"留住的关键
- 备选：完全推迟到 Phase 2，工作量 -15%

---

#### US-2.5 颜色清单展示
**作为** 准备下单的用户  
**我希望** 清楚看到这张图需要哪些色号、各多少颗、是否有货  
**以便** 心里有底，敢下单

**验收标准**：
- [ ] 预览页底部展示色号清单：
  - [ ] 每行：色块（HEX）+ 色号（如 M-023）+ 色名（如"玫瑰红"）+ 颗数 + 库存灯（🟢🟡🔴）
  - [ ] 默认显示前 5 个，可展开看全部
  - [ ] 替换色号显示「~~原色号~~ → 替换色号 + 替换图标」
- [ ] 替换比例显示在清单顶部：「已优化 X 个色号（原色号缺货）」
- [ ] 替换比例 > 20% 时弹窗提示：「这张图替换了较多颜色，建议改用 [推荐难度] 档，效果更好哦」+ 「换难度」「就这样」两个按钮

## 7. 验收与发布

### 7.1 MVP 发布前必过 Checklist

**功能**：
- [ ] 所有 P0 用户故事 AC 100% 通过
- [ ] 所有 P1 用户故事 AC ≥ 80% 通过

**质量**：
- [ ] 100 张样图算法精准度测试报告（优良率 ≥ 75%）
- [ ] 端到端测试：上传 → 收货 全流程跑通 ≥ 5 次
- [ ] 异常流程测试：网络中断 / 支付失败 / 算法超时
- [ ] 关键页面性能测试：首屏 ≤ 2s / 算法 P95 ≤ 10s

**合规**：
- [ ] 微信小程序审核通过
- [ ] 隐私政策 + 用户协议上线（[`./19-*` `./20-*`](.) 待创建）
- [ ] SGS 认证供应商已签约 ≥ 1 家
- [ ] 客服 FAQ + 处理手册就绪

**冷启动**：
- [ ] 至少 30 张真实案例图（用于首页 US-0.3）
- [ ] 100 名内测用户名单
- [ ] 5 位以上小红书 KOL 协议（关联 guihua.md §八）

### 7.2 发布策略
- **第一阶段（W7）**：内测 100 人 + 5 KOL 灰度

- **回滚预案**：算法故障 → 降级为"上一版本镜像"；支付故障 → 暂停下单 1 小时内修复

## 10. 衡量"最好用"的 6 项核心指标

> PRD 不止是功能清单，每个目标必须可量化。MVP 上线后用这 6 项判断是否真的"最好用"：

| 指标 | 公式 | 目标 | 关联 PRD 模块 |
|---|---|---|---|
| **首屏说服力** | 首页 PV → 上传 PV 转化率 | ≥ 40% | M0 |
| **算法满意度** | 生成图纸 → 加购 转化率 | ≥ 50% | M2/M3 |
| **决策信心** | 加购 → 支付完成 转化率 | ≥ 60% | M5/M6 |
| **整体支付转化** | 上述三段相乘（首屏→支付） | ≥ 12% | 综合（M1 门 ≥ 15% 含其他流量） |
| **算法质量** | 100 张样图人工评分优良率 | ≥ 75% | M2 |
| **传播力** | 已完成订单 → 分享次数 | ≥ 25% | M11 |
